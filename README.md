## Project Overview

This project involves the development of a comprehensive website for The Burger Bar, a Durban-based mobile eatery specialising in American-inspired smash burgers. The website will serve as the digital presence for this local brand, which is halal and known for taking the grill to the people, including trading at 246 Currie Road in Morningside.

The Burger Bar website development project spans 12 weeks from 20 July 2026. This structured approach divides the work into three distinct phases, each building upon the previous foundation to create a comprehensive online presence for the business. Part 1 was due on 21 August 2026, Part 2 on 18 September 2026, and Part 3 was completed on 25 October 2026.

The development of this website addresses the current lack of online presence for The Burger Bar. Through research conducted on the brand's Facebook page and related public listings on 20 July 2026, comprehensive insights were gathered regarding business operations, customer needs, and website requirements. This information serves as the foundation for creating a digital platform that accurately represents the brand's values and offerings.

The website showcases The Burger Bar's commitment to serving fresh, high-quality, American-inspired smash burgers that are halal, flavourful, and made to order, while bringing a fun, high-energy food experience to Durban and surrounding communities. 

## Website Goals and Objectives

### Primary Goals
 
The website has been designed to achieve several key business objectives:

**Menu Accessibility:** Customers can view the complete menu online, providing convenient access to all available burgers, sides, and drinks without needing to rely on Facebook posts or phone calls for information.

**Online Ordering Capability:** The platform enables customers to place orders directly through the website, streamlining the ordering process.

**Enhanced Visibility:** The website increases brand awareness and online presence beyond Facebook, making The Burger Bar more discoverable to potential customers in Durban and surrounding areas.

**Promotional Platform:** Special offers are prominently featured on a dedicated Promotions page to drive sales and customer engagement.

### Key Performance Indicators

The success of the website will be measured through several metrics:

- Monthly website traffic to gauge overall reach and engagement
- Number of online orders placed through the platform
- Click-through rates on promotional banners to assess marketing effectiveness
- Bounce rate analysis to evaluate user engagement and content relevance

## Target Audience

The website specifically caters to:

- Local families and individuals residing in Durban
- Students and young adults seeking convenient food options
- Smash-burger lovers across Durban
- Halaal diners looking for trusted preparation information

## Key Features and Functionality

### Essential Pages Structure

**Homepage (index.html):** Full-bleed hero with The Burger Bar branding, short brand introduction, calls to action for ordering and specials, category shortcuts into the menu, a three-photo gallery that opens in a lightbox, and links to the enquiry, map and about pages.

**About Us (about.html):** Brand history, mission and vision, halal preparation information, and Meet the team content for owners and staff with local images that open in a lightbox.

**Menu (menu.html):** The full menu is generated by JavaScript from one data list, with a live search box, category tabs, price and name sorting, a result count, quantity fields and Add to cart forms.

**Promotions (promotions.html):** Current burger-and-chips specials with images, prices, Add to cart forms, and an Order now link.

**Enquiry (enquiry.html):** Bulk order, catering and trading-visit enquiry form that validates the input and instantly shows a cost estimate (bulk discounts, delivery fee, catering set-up fee) and whether the requested date is available.

**Contact (contact.html):** Interactive Leaflet map with four Durban trading spots, Show on map and Find my nearest spot buttons, Google Maps and Apple Maps links, an FAQ accordion, and a validated contact form that compiles the message into an email to the business.

**Checkout (order.html):** Cart review with quantity controls, collection or delivery choice with a delivery fee line, validated customer details, and an order confirmation with a reference number and estimated ready time.

### Core Functionality

**Mobile Responsiveness:** CSS media queries, relative units (`rem`, `%`), and responsive images adapt the layout across desktop, tablet, and mobile breakpoints.

**Location Integration:** Leaflet and OpenStreetMap interactive map with markers, popups and directions links, plus Geolocation API support to find the nearest trading spot.

**Communication Tools:** Contact form that validates input and opens the visitor's email app with the compiled message, an enquiry form with instant cost and availability responses, and a Facebook social link for trading updates.

**Ordering Path:** Add to cart forms on the menu and promotions pages save items to the browser's localStorage, a sticky cart bar shows the running total, and `order.html` handles quantity changes, delivery fees and the final order confirmation.

**Interactivity:** Scroll-reveal animations, a gallery lightbox with previous/next controls, an FAQ accordion, and dynamic menu search, filter and sort, all written in one plain JavaScript file (`js/script.js`).

**Search Engine Optimisation:** Descriptive title tags, meta descriptions and keywords, canonical links, Open Graph tags, structured data (JSON-LD), descriptive image file names and alt text, `robots.txt`, `sitemap.xml` and a custom `404.html`.

## Technical Implementation

The website uses HTML5 for semantic structure, one external CSS stylesheet (`css/style.css`) for visual styling and responsive design, and one external JavaScript file (`js/script.js`) for all interactivity. The JavaScript is written in plain, beginner-friendly ES6 (functions, `const`/`let`, template literals, `querySelector` and `addEventListener`) with a single-line comment above each function explaining what it does. The only external library is Leaflet (loaded from a CDN with Subresource Integrity hashes) for the interactive map.

Security measures include a Content Security Policy meta tag on every page, `escapeHtml()` applied to every piece of user text before it is placed in the page, honeypot fields on all forms to catch spam bots, `rel="noopener noreferrer"` on external links, and a `_headers` file with security headers for Netlify hosting.

Hosting is planned through Afrihost with the domain www.theburgerbardbn.co.za. For Part 3 the site is deployed free of charge on GitHub Pages (see Deployment below).

## Part 3 Details

Part 3 adds JavaScript interactivity, dynamic content, working forms, SEO and deployment. All project JavaScript lives in one file, `js/script.js`, which is loaded with `defer` on every page. Each section of the file checks that the elements it needs exist, so the same file works on every page.

### JavaScript interactivity

- **Dynamic menu (`menu.html`):** The 27 products are stored in a `MENU` array in `script.js` and rendered into the page with template literals. Visitors can search (every word typed must appear in the item name, description, tags or category), filter by category tabs, and sort by price or name. A live result count is announced with `aria-live`, and a Clear button resets everything.
- **Cart and checkout:** Add to cart forms on the menu and promotions pages are handled by one delegated `submit` listener. The cart is saved in `localStorage`, a sticky cart bar shows the count and total, and `order.html` renders the cart with `−` / `+` quantity controls, Remove and Clear cart buttons, a delivery fee line and a grand total.
- **Gallery lightbox:** Any image button with `data-lightbox-src` opens a `<dialog>` lightbox. Images that share a `data-lightbox-group` become one slideshow with previous/next buttons, arrow-key support and an "x of y" counter. Used on the home page gallery, every menu card, the promotions and the team photos.
- **Accordion:** The FAQ on `contact.html` uses buttons with `aria-expanded` and `aria-controls`; only one answer is open at a time and the open/close is animated with CSS.
- **Animations:** Cards fade and rise into view as they scroll into the viewport using the `IntersectionObserver` API, buttons briefly show "Added ✓", and the lightbox image fades in when loaded. All animations respect `prefers-reduced-motion`.
- **Interactive map (`contact.html`):** Leaflet 1.9.4 with OpenStreetMap tiles shows four trading spots with markers and popups. Location cards under the map have Show on map buttons that fly the map to that marker, Show all locations resets the view, and Find my nearest spot uses the Geolocation API (with permission) to find the closest trading spot and how far away it is.

### Forms

- **Validation:** Every form uses HTML5 attributes (`required`, `type="email"`, `type="tel"`, `minlength`, `maxlength`, `min`, `max`) plus JavaScript validation in `validateForm()`. Errors appear under the field, the field is marked with `aria-invalid`, a summary message counts the problems, and the first invalid field receives focus. After the first submit attempt, fields are re-checked as the visitor types. South African phone numbers are checked with a regular expression, and every form has a hidden honeypot field to catch spam bots.
- **Enquiry form (`enquiry.html`):** The item dropdown is filled from the menu data (and pre-selected when arriving from an "Enquire about a bulk order" link). As the visitor changes the quantity a live estimate appears. On submit the script calculates the subtotal, 10% or 15% bulk discount (10 or 25+ items), R250 catering set-up fee and the R35 delivery fee (free over R500), checks availability (closed Mondays, 1–5 days' notice depending on the order, large evening orders only on Fridays and Saturdays) and displays a response panel with a reference number, cost table, next steps, an "Add to cart & checkout" button and an "Email this enquiry" link.
- **Contact form (`contact.html`):** After validation the message is compiled into an email (subject, body, sender details and reference number) using a `mailto:` link to `hello@theburgerbardbn.co.za`, and a confirmation panel shows what was sent.
- **Checkout form (`order.html`):** Validates the customer details (and the address when delivery is chosen), then shows an order confirmation with a reference number, order summary, delivery fee, total and an estimated collection or delivery time based on trading hours, and empties the cart.
- **AJAX:** `sendWithAjax()` posts the form data as JSON with `fetch()` whenever a form has a `data-endpoint` attribute (for example a Formspree or Netlify Forms URL). Without an endpoint the forms fall back to the local processing and `mailto:` behaviour described above, so the site works on static hosting.

### SEO

- Unique, descriptive `<title>` tags and `meta description` and `meta keywords` on every page.
- One `<h1>` per page with a logical `h2`/`h3` hierarchy.
- Canonical links, Open Graph and Twitter Card tags, and JSON-LD `Restaurant` structured data on the home page.
- Descriptive kebab-case image file names and alt text on every image; lazy loading on images below the fold and `fetchpriority="high"` on the hero.
- Clean, readable URLs and internal links between all pages (home links grid, footer navigation, menu-to-enquiry links).
- `robots.txt` (blocks indexing of the checkout page) and `sitemap.xml` listing the six public pages; `order.html` also carries `noindex`.
- Mobile-friendly responsive layout, a skip link and `aria` attributes for accessibility.
- Page speed: a single CSS file, a single deferred JavaScript file, responsive `srcset` images and cache headers in `_headers`.

### Security

- Content Security Policy `<meta http-equiv>` on every page restricting scripts, styles, images and connections to the site itself, Google Fonts, unpkg (Leaflet) and OpenStreetMap tiles.
- All user-supplied text passes through `escapeHtml()` before it is inserted with `innerHTML`.
- Leaflet files are loaded with Subresource Integrity (`integrity` + `crossorigin`) attributes.
- External links use `rel="noopener noreferrer"`; `_headers` sets `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` and `Permissions-Policy` for Netlify hosting.
